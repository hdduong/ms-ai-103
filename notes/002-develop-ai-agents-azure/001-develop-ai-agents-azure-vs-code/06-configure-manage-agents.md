# 06 Configure and manage agents in Visual Studio Code

[Configure and manage agents in Visual Studio Code](https://learn.microsoft.com/en-us/training/modules/develop-ai-agents-azure-vs-code/6-configure-manage-agents?pivots=text)

- This YAML is a declarative prompt agent. Hosted agents are code. Workflow agents use a different schema.
- Designer and YAML stay in sync. You set the name, the model deployment, the description, the instructions, and the extension generates the agent id.
- Learn suggests temperature around 0.1–0.3 for steady answers, 0.7–1.0 for variety, and 0.3–0.7 for business scenarios; top p defaults to 1.0. These are tuning examples for models that accept those parameters. Check the selected model before adding them to YAML.
- Commit the YAML. One agent, one job. Test in the playground after each change.

## Prompt agent

```yaml
# yaml-language-server: $schema=https://aka.ms/ai-foundry-vsc/agent/1.0.0
version: 1.0.0
name: healthcare-assistant
description: Schedules appointments and answers policy questions
id: agent-abc123xyz
metadata:
  authors:
    - developer-name
  tags:
    - healthcare
    - scheduling
model:
  id: gpt-4.1 # deployment name
  options:
    temperature: 0.5
    top_p: 1
instructions: |
  You help staff schedule appointments.
  Never share patient medical information.
tools: []
```

For the IT support example, inspect the YAML generated by Agent Builder for `it-support-agent`. The `model.id` must match your deployment, and its instructions should still require the uploaded policy for policy questions. The healthcare YAML above is a schema illustration, not a replacement for your saved IT support agent or its file bindings. Save a change, test it in the playground, and compare the generated YAML so you can connect each designer setting to its configuration field.
